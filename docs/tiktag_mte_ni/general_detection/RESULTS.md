# Making precondition-gated speculative leaks fuzzer-detectable — results

Status of the Step 0->4 ladder for driving the GENERAL class of precondition-gated speculative leaks
through Revizor's non-interference template/fuzzer pipeline, TikTag-v1 (MTE tag-match) first.

All artifacts are under `docs/tiktag_mte_ni/general_detection/`. Device: Pixel 8 Cortex-X3 (core 8),
adb 127.0.0.1:5037. venv `/home/gal_k_1_1998/revizor/revizor-venv/bin/python`. Full step-by-step
evidence (commands + verbatim numbers) is in `LOG.md`.

## Headline

Step 1 is ACHIEVED: the non-interference fuzzer reports a GENUINE TikTag-v1 violation on a Revizor
template, confirmed by the verify-mte-tag-leak tag-tracking control. The leak mechanism reproduces every
time; the fuzzer's violation *report* is run-to-run probabilistic and was hardened (see Reliability).

## What blocked the literal Step 1, and the fix

- The literal plan (internal-loop ASM template + MteSealing) is IMPOSSIBLE as stated: the sealer's
  sandbox/taint walk requires a DAG CFG (`primitives.py _topo_sort` raises "CFG contains a cycle; MTE
  taint dataflow assumes a DAG", unconditionally; no loop unrolling exists in the pipeline). Any looped
  template is rejected at `load_test_case` before anything else. The internal-loop training the task
  assumed is therefore unavailable through the sealer.
- Fix: a LOOP-FREE (DAG) template whose tag-checked body sits on the branch's ARCH-NOT-TAKEN path. Then
  the body load is reached only speculatively (CE min-nesting > 0) -> sealer-eligible (`has_decoy=True`),
  and the MTE sealer decoys it with a mismatched tag (genuine ADDG retag to the cell tag vs decoy ADDG
  to a wrong tag). A body-arch control (branch arch-not-taken) is correctly ineligible.
- The misprediction window is supplied by the NATURAL cold/late-resolve misprediction of an arch-taken
  forward branch fed by a long SDIV compute chain (confirmed to open even with kernel branch-mistraining
  OFF). Kernel per-input mistraining (measurement.c `apply_input_branch_training`) also opens it and is
  available, but is not required.

## The working gadget (Step 1)

Loop-free DAG template (`s1_tiktag_hard.asm`, generated by `gen_s2.py`):
- arch prologue warms+zeros the guess granule (matching tag, never faults);
- a deep SDIV chain feeds an arch-taken forward branch (`ORR x9,x9,#1; CBNZ x9,.skip`) that is
  mispredicted into the never-architectural body;
- body: ONE tag-checked guess load `LDR x12,[x5]` (sealer-decoyed), a data-dependent latency gate
  (`AND x11,x12,xzr; ORR x10,x10,x11` x gap) that holds the probe at a FIXED set 32 while making it wait
  on the guess result, then the probe `LDR x13,[x10]`.

Critical tuning (from the sweeps in LOG.md, Exp 5-6):
- Track a FIXED probe set (set 32). The guess load's OWN line allocates regardless of tag; the leak is
  the DOWNSTREAM probe (TikTag-v1), so tracking the guess line hid the effect (Exp4 false null).
- Put the probe at the window EDGE (short gate, gap~=8): baseline probe residency ~0.5 (matching the
  manual PoC's ~0.62 marginal window); a wide gate pushes the probe off the window in both variants.
- ldnum=1 (single guess load feeding the gate) so the fuzzer's RANDOM decoy actually perturbs the
  gate-feeding load (ldnum>=4 dilutes it: the random subset leaves the last load matching too often).

## Genuineness (verify-mte-tag-leak)

- noncanon (all speculative loads mistagged): probe set 32 collapses 0.5->0.02 while the guess line
  stays resident 1.0 -> the leak is the downstream probe gated by the tag check, not the checked load's
  own residency.
- Tag-tracking control (sweep the speculative retag delta 0..15, probe set 32 residency): present only
  at the MATCH tag and a TCMA-unchecked tag; absent at every checked mismatch. Sharp tag-dependence, not
  uniform firing -> genuine MTE tag-CHECK leak. (Full numbers in LOG.md Exp 8.)
- No architectural fault/crash: the mistagged access is speculative-only.

## Step 2 (swap the precondition): canonicality — ACHIEVED

`s2_canon_hard.asm` + `s2_canon_hw_hard.yml` (`enable_canonicality: true`, no MTE/PAC categories). Same
DAG-neverarch skeleton; CanonSealing makes the speculative guess load's pointer non-canonical in the
decoy. HW (measure_variants): baseline 1.0 -> decoy/noncanon 0.0 — a CLEAN, near-binary divergence, and
the RANDOM decoy shrinks too. Fuzzer: Violations: 1 (Fast Path 0).

Mechanism note: for canonicality the divergence is at the guess load's OWN line (a non-canonical
speculative address is squashed before it allocates), whereas for MTE the checked-load line stays and
only the DOWNSTREAM probe shrinks. Both are precondition-gated speculative cache leaks; canonicality is
the cleaner (binary) signal.

## Step 3 (fuzz the body in a fixed skeleton): ACHIEVED (canonicality)

`s3_canon_randbody.asm`: fixed det-SDIV window + arch-taken `CBNZ`, and the speculative body is a
`.macro.random_instructions.32.8.0` block the FUZZER fills. CanonSealing seals the fuzzer-generated
speculative loads. HW: baseline hottest set 1.0 -> ALL decoys + noncanon ~0.0 (robust; many sealed loads
so any random decoy perturbs an observed one). Fuzzer: Violations: 1 (Fast Path 0). The fuzzer now
contributes STRUCTURE, not just the precondition value.

## Step 4 (fully random generation): PARTIAL

`s4_canon_random.yml`, `revizor.py fuzz` (no template), canonicality NI: 40 random programs -> 1 reported
violation (Fast Path discarded 32; Duration 216s). The fully-random path DOES surface a precondition-
gated canonicality violation, but at low yield (~1/40) — the generator does not bias toward the needed
structure (an arch-not-taken forward branch with a long resolve and a speculative sealed access on the
mispredicted path). By NI construction (baseline vs its own decoy, only the seal differs) the violation
is canonicality-seal-driven. Capability demonstrated end-to-end; the yield is the open gap.

## Most promising next step

Raise the Step-4 yield with a structure-biased generator: have the program generator emit, with some
probability, an arch-taken forward conditional branch fed by a long compute/dependent chain (so it
resolves late and the cold forward-branch prediction speculates the fall-through), with the sealer's
precondition access placed on that mispredicted path. That turns the rare random hit (1/40) into a
common one while keeping the leak fuzzer-discovered rather than templated. Also: extend Step 2 to PAC
(PacSealing needs a speculative AUT* in the gadget and per-input pac_keys) and SignExt for more
preconditions.

## Reliability (coordinator lever #2)

Default analyser is `chi2` (probabilistic; `analyser_outliers_threshold` applies only to sets/bitmaps).
The underlying leak reproduces every run (measure_variants/tag-sweep). The fuzzer's violation REPORT for
the single-load MTE gadget is probabilistic (~75%, 3/4 runs) because (a) the random decoy subset
perturbs the single guess slot only ~50% of the time and (b) the MTE window is marginal (~0.5 baseline).
Hardening: input-independent (fixed-divisor) SDIV window, `inputs_per_class: 4`, larger sample. The
canonicality gadgets are much more reliable (binary 1.0->0.0, all decoys diverge).

## Addendum 2 — the USER'S mostly-random skeleton DOES find genuine TikTag (correction)

user_mte_skeleton.asm = random / planted window / random / if(planted){ random / ONE sealed load /
random } / random. NO deliberate probe, NO warm — only the window + one sealed load are planted; the
downstream is random. Single `-n 1` run = 0; an extended run (40 fills x 10 inputs, flush ON,
s1_mte_hw_hard_noMT.yml) produced 3 violations.

DECISIVE 16-tag sweep on the REAL violation input #5 (triage_sweep.py; knockout to find the leaking
sealed load, then sweep its tag 0..15 at the diverging set):
- violation 155905 (set 9): delta 7 (match) = 1.00, ALL other tags 0.00-0.05  => TEXTBOOK genuine TikTag.
- violation 160128 (set 39): match(7)=0.57 + delta0=0.54 (TCMA-unchecked), all checked mismatches
  0.06-0.18 => GENUINE tag-check.
- violation 160705 (set 32): uniform 0.55-0.65 across all tags, match mid-range => NOISE.
=> 2 of 3 GENUINE TikTag, 1 noise. (Stability recheck in LOG.)

IMPLICATION: a mostly-random template (window + one sealed load planted, downstream random) DOES
auto-detect genuine TikTag, at a low rate (2 genuine / 40 fills here). This corrects the earlier,
single-run-based claim that the user's skeleton "only gives gain-flavor / can't do clean MTE": that was
an artifact of (a) one -n1 run and (b) fresh-input measurement (set/load are input-specific). The random
tail can supply a dependent downstream access inside the window; when it does, the tag mismatch cleanly
shrinks it. The fully-planted gadget is still higher-yield/reliable, but random-ish detection is real.
